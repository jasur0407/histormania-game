It is going to be a mobile 2d game mostly for android, similar to "Choice of Life". But the main difference is all the scenarios are based on the history and historical events. I want to create many paths for the user to choose from - a player is going to be act behalf of a person in one specific time frame in the history and events. Each path will take place in some time frame in history and is not going to be long like in "Choice of Life" - it going to be relatively shorter but there is gonna me many paths to choose from and we can a hearts  to make it more engaging and challenging - applying penalty to potentially wrong choices.

Characters:
Every character should have their own consistent personality throughout each path. While coming up with characters pay attention to diversity like playful, serious, fearful, neutral, passionate, ambitious, hard working characters.

Game rules:
Each paths is going to be about different historical time periods and the user is going to act behalf of one specific main character. At the start of the each path user will have limited amount of hearts. Only some event choices will affect those, adding and subtracting from them. Each choice should have 2 choices to choose from. 

Zero hearts:
Treat zero hearts as a _bad ending_, not a failure state — a short but complete narrative conclusion (exile, ruin, death in-story) that still feels like part of the story, with an easy "try again from this chapter" option. Failure becomes content instead of punishment.

Penalty choices:
Always show a brief consequence line right after a costly choice ("Your refusal to pay the toll collector will be remembered")

Main character (user):
A fictional character (a merchant, soldier, citizen) living through real events gives you total freedom to branch meaningfully while real figures appear as NPCs. Almost always the better answer for a branching game.

True branching vs. "beads on a string" structure
Pure exponential branching is why solo narrative games die mid-development — a 20-choice tree branching freely produces millions of end states. The fix that actually improves the experience (not just saves you time): fixed checkpoint scenes with forking paths _between_ them that reconverge before the next checkpoint. Players still feel real agency in the moment without you writing an unmanageable tree.

Auto-save:
Chapters of 10–15 minutes with autosave between them dramatically improve retention over one unbroken flow — and it gives you natural checkpoints to pair with the failure-state design above.

Coins:
1. **Buying back a heart — but rarely and expensively**  
A doctor's fee, a bribe to avoid execution, hiring a bodyguard after a bad fight. This gives coins real stakes-relief value, but if it's cheap or repeatable, hearts stop meaning anything. Keep the price steep and maybe limit it to once or twice per path so players still have to play carefully.
2. **Paying for information**  
A fortune teller, scribe, spy, or informant who gives a hint about what a choice might cost before you commit. This is powerful because it's historically flavorful (period-appropriate ways to "buy knowledge") and it turns coins into a hedge against the guesswork the hearts system otherwise punishes.

MOST IMPORTANT:
Avoid designing toward one right answer per decision — real people living through events didn't know the outcome either. Make sure at least two options at each major fork are period-plausible with different costs, so it plays like a genuine dilemma rather than a trivia quiz with a hidden answer key.
